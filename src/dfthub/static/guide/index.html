Guide

How to use DFThub

Fit a density functional to your own reactions, check how it behaves, and export the results. This guide walks through each step.

About 8 minutes Covers Workspace, Analyze and figure export
  1. Prepare your dataGeometries as .xyz files in one .tgz, plus a .ref file of reference energies.
  2. Submit a jobUpload both files, pick an inverse weight and a basis set.
  3. Follow progressFour stages, with submission and completion notifications.
  4. Tune and resubmitAdjust database weights until the balance suits you.
  5. Analyze and exportCompare runs and save Nature-style figures.

Before you start

Sign in or register so your jobs stay in one place. You need two files for each data set (next section). These terms appear throughout the site:

Job
One data set and everything computed from it, identified by its Job ID, such as dft_dvvini.
Run
One fit inside a job. New fits are numbered weight_0, weight_1, and so on.
Fork
A run made by tuning the database weights of an existing run, such as weight_2/fork-1. It is evaluated on its parent's densities, so it is quick.
Inverse weight
How much a data set counts in the fit. Lower means it counts more.
MUE
Mean unsigned error against the reference energies, in kcal/mol. Lower is better.
Input MUE
MUE on your own data set. Non-SCF reuses the parent run's densities; SCF recomputes them self-consistently.
CF22D original
The published CF22D parameters. Every change is measured against them.
Reference datasets
The built-in training databases (91 of them) that keep the functional general.
01Step 1

Prepare your data

A data set is two files: your structures and the reference energies the functional should reproduce.

GeometriesOne .tgz archive of .xyz files

One .xyz file per molecule or transition state. Line 2 holds the charge and spin multiplicity.

3
0 1
O    0.000000    0.000000    0.117300
H    0.000000    0.757200   -0.469200
H    0.000000   -0.757200   -0.469200
  • 3 number of atoms
  • 0 1 charge, spin multiplicity
  • O x y z element and Cartesian coordinates, one atom per line

Pack the files into one archive:

tar -czf YourDatabaseName.tgz *.xyz
Optional test setA second .tgz and .ref pair

Upload a separate test archive and reference file when you want an independent evaluation. The test set is excluded from optimization and is reported separately after the training calculation.

Reference energiesOne .ref file

Lists each reaction as a formula of your molecule names, with its reference energy from experiment or high-level calculations such as CCSD(T)/CBS.

The template shows the exact layout. Start from it rather than writing the file from scratch.

Download template

Check before you upload

  • Each .xyz file holds one molecule or transition state, with its charge and spin multiplicity on line 2.
  • Every file in the archive has a unique name.
  • Molecule names in the .ref file match the .xyz file names exactly.
  • Reference energies come from experiment or high-level theory, such as CCSD(T)/CBS.
02Step 2

Submit a job

Click New job in the top bar, or press N. Fill in the form; Submit job becomes available once both files are added.

FieldWhat to enter
Job IDLetters, numbers, - and _. A random ID is suggested; regenerate it or type a name you will recognise.
EmailWhere DFThub writes when each step finishes.
Geometries (.tgz)Drop your archive on the box, or click to choose it.
Reference energies (.ref)Your training .ref file, the same way.
Optional test setA paired test .tgz/.ref upload in Advanced settings; it is excluded from optimization.
Initial inverse weight0.001–10, default 0.02. Type a value or use the slider (see below).
Zeta levelBasis-set size, from Minimal to Quintuple.
Core electronsAll-electron, or ECP to replace core electrons with an effective core potential.
Final basisSuggested from the two choices above, for example def2-QZVP. Change it if you need another.
NotesOptional, up to 500 characters, for anything the team should know.

Choosing the inverse weight

It sets how strongly your data set pulls on the fit compared with the built-in training databases. A lower value fits your reactions more closely, but the reference databases may get worse. Start with the default; you can change it later and every run stays available for comparison.

05Step 5

Tune and resubmit

Rarely is the first fit the right balance. Tuning lets you try new weights quickly, then commit to a full fit.

weight_0 weight_1 weight_2 fork-1 fork-2 fork-3 weight_3
New fit, self-consistent Fork: tuned weights on the parent's densities Next resubmission
  1. Tune weightsIn a completed run, click Tune weights and change the inverse weight of any database. Lower values make it count more.
  2. Compare forksEach set of tuned weights is saved as a fork of the run. Compare their MUE in the Workspace, or side by side on Analyze.
  3. ResubmitWhen the balance suits you, resubmit with the new weights. This runs a full fit as the next run (for example weight_3); your current run stays available.
  4. Calculate InputClick Calculate Input for the self-consistent Input MUE. Open Self-consistent results and select AME418 for the benchmark or DFT energy to evaluate an uploaded archive molecule by molecule without a reference file.
Forks are quick estimates on stored densities. Check the SCF Input MUE before you report a result.

Click Analyze in the top bar to compare every run of a job on one page.

  1. 1Pick the runs. In the sidebar, tick the runs to include and click one to focus it; the focus run is highlighted in every chart.
  2. 2Choose a view. Trends shows MUE across runs and the trade-off between your data set and the reference databases (lower-left is better).   3. 3Check the baseline. Every change is compared with the original CF22D parameters.
  4. 4Explore the charts. On MUE across runs, open Series and click Add reference datasets to plot up to four datasets, and switch to Log when their values differ a lot. Open Series to show or hide individual curves.
Which run to keep? On Trends, look for points near the lower-left of the trade-off chart. The faint blue line joins the runs that no other run beats on both your data set and the reference databases.

Export figures

Every chart on Analyze has Export. It redraws the chart in Nature's figure style (Arial 5–7 pt, black text, thin axes, no gridlines) and shows a preview before you download.

FormatSVG keeps text editable and is the one to submit. PNG suits drafts and slides.
Width89 mm (single column), 120 or 136 mm, or 183 mm (double column).
ResolutionPNG at 300 or 600 dpi, stored in the file.
Panel labelOptional letter, such as a, set in 8 pt bold.

The figure shows exactly what the chart shows: the runs you included, datasets you added, the log scale, and for the heatmap, the rows left after searching and filtering. For a journal that wants PDF or EPS, open the SVG in Illustrator or Inkscape and save it in that format.

Questions and help

My upload is rejected. What should I check?

Most problems are names: every .xyz file needs a unique name, and the names in the .ref file must match them exactly. Also check that line 2 of each .xyz file holds the charge and spin multiplicity. The template shows a working example.

The reference databases got worse. What now?

That is the trade-off of a strong pull from your data. Raise the inverse weight of your data set in the next resubmission, or use Tune weights to lower the inverse weight of the databases you care about most. Compare the results on Analyze.

Why is the SCF Input MUE higher than the non-SCF one?

The non-SCF value reuses densities from the parent run. The SCF value lets the density relax with the new parameters, which usually shifts the error a little. The Input vs SCF view on Analyze shows the gap for every run.

Can I delete a job?

Yes, from the job list in the Workspace. Deleting removes the uploaded files, all runs and all results, and cannot be undone. An active queued or running calculation must finish or be stopped before its job can be deleted.

Can I script DFThub?

Yes. The API docs describe the endpoints for uploading files, submitting jobs and downloading results.
